# Безкоштовне розміщення на PythonAnywhere

Перевірено за офіційними джерелами 25.10.2026. Застосунок **не опубліковано**. Наступні дії виконує користувачка після окремого дозволу на публікацію.

## Чому Free підходить для цього демо

- [Free](https://help.pythonanywhere.com/pages/FreeAccountsFeatures/): один вебзастосунок, один worker, 512 MiB диска, строк запуску один місяць. Цього достатньо за місткістю для двох людей і невеликих навчальних виписок; локально середовище залежностей займає близько 86 MiB, на хостингу розмір перевіряємо окремо.
- [Flask через WSGI](https://help.pythonanywhere.com/pages/Flask/): запускає платформа. gunicorn не потрібний; `app.run()` на хостингу не використовуємо.
- [SQLite доступна всім](https://help.pythonanywhere.com/pages/KindsOfDatabases/). Для цього малого демо залишаємо один worker, короткі транзакції та файлове блокування. PythonAnywhere застерігає щодо SQLite для навантажених production-застосунків; масштабування тут не обіцяємо. База лежить у домашній папці, не в /tmp і не в каталозі публічних файлів.
- [Безкоштовний SSL](https://www.pythonanywhere.com/pricing/) на домені акаунта; [Force HTTPS](https://help.pythonanywhere.com/pages/ForcingHTTPS) вмикається на вкладці Web. Власний домен не купуємо.
- Вхід локальний на Flask/Werkzeug, два різні акаунти. Supabase не потрібний; немає зовнішніх auth-запитів, проблем із мережевим allowlist чи засинанням іншого сервісу. Нових бібліотек не встановлено: Fava 1.30.16, Flask 3.1.3, Werkzeug 3.1.9 уже були в проєкті та зафіксовані в uv.lock.

Рішення уточнює попередню архітектуру Supabase/Railway лише для практичного демо згідно з останнім дозволом обрати найпростіший безпечний вхід. Грошових платежів чи підключення тарифів не виконано.

## 1. Підготувати файли локально

```sh
uv run --frozen python verify.py
uv run --frozen python manage.py bundle
```

Отримаєте outputs/tracker-deploy.zip. У ньому код, lock-файл, тести й дві штучні виписки; немає data/, журналу користувачів, SQLite, паролів, env.json чи git-історії. Архів не створює публікацію. Не додавайте до нього runtime/.

## 2. Підготувати акаунт і середовище

1. Увійти або створити **Beginner / Free** акаунт PythonAnywhere без платного плану.
2. Через Files завантажити й розпакувати архів у `/home/YOUR_USERNAME/my-finance`. Можна використати стандартне розпакування ZIP у Bash-консолі. Якщо архів розгорнуто у GitHub після дозволу, можна натомість клонувати цей репозиторій.
3. Потрібні доступні Python 3.12 та uv. Віртуальне середовище Web має використовувати **ту саму версію Python**. Якщо uv відсутній, спочатку встановіть його за [офіційною інструкцією uv](https://docs.astral.sh/uv/getting-started/installation/) або через підтримку середовища; залежності самого проєкту далі встановлюємо тільки через uv.
4. У Bash-консолі перейти в каталог проєкту, виконати:

```sh
UV_NO_CACHE=1 uv sync --frozen --no-dev
uv run --frozen python import.py
uv run --frozen bean-check main.beancount
uv run --frozen python verify.py
```

UV_NO_CACHE не залишає завантажені колеса в дисковій квоті. Команда перевірки повинна завершитися з кодом 0, усі тести — OK. Якщо не вистачає квоти чи потрібної версії Python, зупинитися й перевірити середовище; платний план не вмикати.

## 3. Налаштувати секрети

У каталозі проєкту:

```sh
uv run --frozen python manage.py configure --origin https://YOUR_USERNAME.pythonanywhere.com
```

Для EU-акаунта використовуйте точну адресу з вкладки Web. Команда попросить два **різні нові паролі від 12 символів**, без показу на екрані. Логіни — `ola` і `marko`. У runtime/env.json із правами 600 зберігаються випадковий ключ сесій та сольовані scrypt-хеші, а не відкриті паролі. При запуску вони читаються як конфігурація середовища; справжні змінні оточення мають пріоритет. runtime/ виключено з git та архіву.

Не надсилайте env.json у чат і не включайте до публічного репозиторію. Новий секрет при кожному перезапуску не генеруйте — він має залишатися сталим. Зміна пароля/ключа скидає старі сесії. Креденсіали для викладача передаються окремо у формі здачі, не в README.

## 4. Налаштувати Web

1. Web → Add a new web app → безкоштовний домен → **Manual configuration → Python 3.12**.
2. Virtualenv: `/home/YOUR_USERNAME/my-finance/.venv`.
3. У WSGI configuration file залишити наступний код, підставивши власне ім’я:

```python
import os
import sys

project = '/home/YOUR_USERNAME/my-finance'
if project not in sys.path:
    sys.path.insert(0, project)
os.environ['TRACKER_ENV_FILE'] = project + '/runtime/env.json'
# Тільки тут, за reverse proxy PythonAnywhere. Не вмикати для відкритого локального сервера.
os.environ['TRUST_PROXY_HEADERS'] = '1'
from wsgi import application
```

4. Увімкнути **Force HTTPS**, натиснути Reload. Проксі дозволений лише у цьому розміщенні; застосунок також відхиляє обробку фінансових запитів через HTTP й використовує фіксований домен.
5. **Static files mappings залишити порожніми.** Не публікувати каталог проєкту, runtime/, data/, report.html чи Beancount-файли. CSS/JS Fava видає захищений застосунок; сторінка входу має лише загальний CSS.
6. Не запускати gunicorn, fava CLI чи development server у Bash, щоб зробити сайт публічним: його обслуговує WSGI платформи. Залишити один worker.

Папка runtime/ з SQLite, сесіями, конфігурацією й приватними проєкціями журналів повинна зберігатися між Reload/оновленнями. Повторне завантаження коду не повинно видаляти цю папку.

## 5. Приймання після публікації

- У приватному вікні відкрити HTTPS: до входу немає цифр, файли `/report.html`, `/runtime/tracker.sqlite3`, `/main.beancount` та адреси Fava теж закриті.
- HTTP переводить на HTTPS. Перевірити сертифікат та відсутність циклу перенаправлень; секрети через HTTP не вводити.
- Увійти як marko на телефоні, вибрати серпень/вересень. Банківські змінні: 1855,57 / 2432,83 PLN. Окремо ola: 2195,21 / 2582,42. Чужий префікс журналу не відкривається.
- На окрему тестову дату після 15.10.2026 додати 1 PLN у тестовому сховищі, оновити сторінку, натиснути Reload у Web: запис повинен залишитися один раз. Повторний імпорт банків його не стирає. Не додавайте тест у контрольні CSV. Для фінального показу краще використовувати окремий тестовий акаунт PythonAnywhere/копію runtime, якщо потрібно залишити робочий журнал без тестових покупок.
- Увійти/вийти в Safari iOS і Chrome Android: читабельні суми, поля, клавіатура, немає загального горизонтального прокручування. Локальні автоматичні перевірки не є тестом реального телефона.
- Запустити `uv run --frozen python verify.py`: тести додають 1 PLN тільки у тимчасові бази, не в поточне runtime/ і не у виписки.
- Записати адресу, дату успішної перевірки та строк запуску на Web. **Expiry / run until має бути не раніше 10.11.2026**, щоб покрити 9 листопада включно. За потреби безкоштовно продовжити запуск кнопкою на Web; перевірити сайт перед здачею та 8–9 листопада. Одномісячний термін не є автоматичною гарантією доступності конкретного акаунта.

Публічний HTTPS-сценарій і доступність до 9 листопада ще не перевірені: публікацію не виконано.

## Резервна копія

```sh
uv run --frozen python manage.py backup runtime/backup-2026-10-26.sqlite3
```

Команда використовує SQLite backup API та не перезаписує наявну копію. У копії очищено сесії й лічильники входу, щоб відновлення не повертало вже відкликаний доступ. env.json зберігайте окремо захищено. Для відновлення зупиніть Web, збережіть поточний runtime/, замініть tracker.sqlite3 перевіреною копією, залиште env.json і перезапустіть: приватні Beancount-проєкції відновляться з бази та незмінених прикладів, користувачі увійдуть повторно. Не видаляйте робочу базу заради нового імпорту.
