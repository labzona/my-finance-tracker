# Фінансовий трекер Олі та Марка

Python / Beancount 3 / Fava. Використовуються лише дві штучні навчальні виписки, PLN. На 25.10.2026 готові імпорт обох банків і відтворювана перевірка; вхід, готівка та HTTPS-деплой ще не реалізовані. [Аудит до змін](homework/18-implementation-audit.md), [план реалізації](IMPLEMENTATION_PLAN.md).

## Одна команда перевірки після клонування

Потрібні Python 3.12+ та uv. З кореня репозиторію:

```sh
uv run python verify.py
```

Команда звіряє SHA-256 навчальних джерел, заново будує журнал у тимчасовій папці, запускає `bean-check` і друкує контрольні змінні витрати. За помилки залишку, обліку, джерел чи контрольної суми завершується з ненульовим кодом. Локальні data/, transactions.beancount і report.html не змінює. Перший запуск uv встановлює залежності з проєкту; для перевіреного зафіксованого середовища можна використати `uv run --frozen python verify.py`.

25.10.2026 перевірено в чистому локальному клоні без data/ і згенерованого журналу: встановлення залежностей за uv.lock з наявного кешу, verify.py, import.py та окремий bean-check пройшли. Це локальна перевірка відтворення, а не вже опублікований HTTPS-сервіс.

Це банківські витрати з умови, до перерозподілу спільних часток. Початкові залишки не є доходом. Розрахунок особистих часток 50/50 — наступна функціональність; не підміняємо ним контрольні цифри.

## Локальний облік і звіт

```sh
uv run python import.py
uv run bean-check main.beancount
uv run python report.py
uv run fava -p 5050 main.beancount
```

Імпорт читає data/ для Олі, якщо папка є; після клонування використовує examples/ola-statement.csv. Марка читає з examples/marko-statement.csv; інший шлях можна вказати `--marko`. Підтримано два відомі формати з умови та початкові залишки 4500 / 2860,40 PLN. Для контрольних прикладів `uv run python import.py --ola-dir examples` відтворює обидва джерела незалежно від локального data/.

Залишок перевіряється після кожного рядка, без сортування часу всередині дня. Польська виписка розгортається зі зворотного банківського порядку. Повторні рядки не подвоюються; власник входить до ключа. Неправильний залишок/валюта/порядок зупиняє імпорт до заміни попереднього журналу. Виписки з непослідовними чи неповними діапазонами потрібно звірити, а не мовчки сортувати.

report.html поки показує Олю за календарними місяцями. Повторно використаний `report.load_report("marko")` повертає окремі суми Марка. Чотири збережені query у Fava залишаються особистими запитами Олі. Теги власника відокремлюють розрахунки, але ще не є захистом доступу. Сирі файли й локальну Fava не публікуйте; вебвхід і серверні права ще попереду. Зарплатні періоди основного PRD не підміняють календарні контролі домашки.

## Тести

```sh
uv run python -m unittest discover -s tests -v
```

Перевіряються обидва контрольні місяці, дублікати й повторний імпорт, кожний банківський залишок, відмова при помилці без втрати попереднього журналу, валюта, нормалізація сум, правила fixed та ізоляція розрахунків за власником.

## Дані й файли

- examples/ — лише незмінені штучні виписки з умови та їх походження/хеші; дозволені для відтворення після клонування. Справжніх виписок тут бути не повинно.
- data/ — лише читання. data/, transactions.beancount, report.html, .venv/ не потрапляють у git.
- main.beancount — рахунки, два початкові залишки й нативні query; import.py генерує банківський журнал; категорії та fixed задає тільки rules.csv.
- homework/ — продуктовий документ, декомпозиція та кроки частини 2.

Готовність 2/2 ще не підтверджена: потрібні стійке сховище готівки, Supabase-вхід і права, безкоштовний HTTPS, мобільне приймання та перевірка доступності до 09.11.2026 включно. Платні послуги не підключалися.
