# Фінансовий трекер Олі та Марка

Python / Beancount 3 / Fava. Використовуються лише дві штучні навчальні виписки, PLN. Реалізовано два входи, приватні звіти Fava й постійну готівку. За повідомленням користувачки трекер уже розміщено на PythonAnywhere Free: HTTPS, вхід Марка, звіт на телефоні та збереження 1 PLN після оновлення перевірені нею. [Налаштування хостингу](deploy/PYTHONANYWHERE.md), [реалізація й локальні перевірки](homework/19-web-implementation.md).

## Встановлення після клонування

Потрібні Python 3.12+ та [uv](https://docs.astral.sh/uv/getting-started/installation/). Клонуйте репозиторій або завантажте його код, відкрийте каталог проєкту в терміналі й виконайте:

```sh
git clone https://github.com/labzona/my-finance-tracker.git
cd my-finance-tracker
uv sync --frozen
uv run --frozen python verify.py
```

Перший запуск потребує доступу до реєстру пакетів, якщо залежностей ще немає в кеші. Перевірка не потребує паролів, акаунта PythonAnywhere, локальної data/ чи робочої бази. Для локального входу створіть **власні окремі** паролі наступною командою configure; дані входу опублікованого трекера до репозиторію не додавайте.

## Вебверсія

Уже встановлені Fava/Flask/Werkzeug використано повторно. У Fava додано невелике розширення місячного звіту й форми готівки, окремого frontend-застосунку немає. Кожен акаунт отримує лише свій серверний журнал; довільні браузерні запити BQL, сирі файли, імпорт і редактор Fava закриті. Для поточного демо Supabase і gunicorn не потрібні: PythonAnywhere обслуговує WSGI сам.

Готівка живе в runtime/tracker.sqlite3; повторний імпорт банків її не перезаписує. Є захист повторного надсилання, CSRF, обмеження спроб входу, Secure/HttpOnly/SameSite cookie, вихід із відкликанням сесії та строки 30 хв бездіяльності / 8 год загалом. Вхід і фінансові маршрути у звичайному режимі обслуговуються лише через HTTPS; невідомі домени відхиляються.

Паролі задає користувачка, у коді готових облікових даних немає. У середовищі зберігаються сольовані scrypt-хеші та випадковий ключ. Захищений runtime/env.json (600) — локальне джерело цих змінних для WSGI; справжні змінні оточення мають пріоритет. runtime/ не комітиться й не входить до архіву.

Для локальної перевірки на власному ноутбуці:

```sh
uv run --frozen python manage.py configure --origin http://127.0.0.1:5050 --local-http
uv run --frozen python manage.py serve
```

Цей HTTP-режим дозволений тільки на loopback і слухає лише 127.0.0.1:5050; не використовуйте його для публікації. На хостингу створіть **окрему** конфігурацію з HTTPS без --local-http, за інструкцією. Не копіюйте локальний runtime/ на публічний сервер. Якщо конфігурація вже є, configure відмовляється мовчки її перезаписувати.

## Одна команда перевірки після клонування

Потрібні Python 3.12+ та uv. З кореня репозиторію:

```sh
uv run --frozen python verify.py
```

Команда звіряє SHA-256 навчальних джерел, заново будує журнал у тимчасовій папці, запускає `bean-check`, друкує контрольні змінні витрати та виконує всі **25 тестів**. За помилки завершується з ненульовим кодом. Локальні data/, transactions.beancount, report.html і робочий runtime/ не змінює. Тестова 1 PLN додається тільки в тимчасові бази. Для зафіксованого середовища використовуйте `uv run --frozen python verify.py`.

Команду перевірено в чистій локальній копії без data/, runtime/, секретів і згенерованого журналу. Це перевірка відтворення коду; результат зовнішнього HTTPS-сценарію наведено вище окремо за повідомленням користувачки.

| Власник | Серпень 2026, PLN | Вересень 2026, PLN |
|---|---:|---:|
| Оля | 2195,21 | 2582,42 |
| Марко | 1855,57 | 2432,83 |

Це банківські витрати з умови, до перерозподілу спільних часток. Початкові залишки не є доходом. Розрахунок особистих часток 50/50 — наступна функціональність; не підміняємо ним контрольні цифри.

## Локальний облік і звіт

```sh
uv run python import.py
uv run bean-check main.beancount
uv run python report.py
uv run fava -p 5050 main.beancount
```

Імпорт читає data/ для Олі, якщо папка є; після клонування використовує examples/ola-statement.csv. Марка читає з examples/marko-statement.csv; інший шлях можна вказати `--marko`. Підтримано два відомі формати з умови та початкові залишки 4500 / 2860,40 PLN. Для контрольних прикладів `uv run python import.py --ola-dir examples` відтворює обидва джерела незалежно від локального data/.

Залишок перевіряється після кожного рядка, без сортування часу всередині дня. Польська виписка розгортається зі зворотного банківського порядку. Повторні рядки не подвоюються; власник входить до ключа. Неправильний залишок/валюта/порядок зупиняє імпорт до заміни попереднього журналу. Виписки з непослідовними чи неповними діапазонами потрібно звірити, а не мовчки сортувати.

report.html лишається локальним календарним звітом Олі; `report.load_report(owner)` повторно використано у приватних журналах вебверсії. Команда fava вище — лише локальний перегляд **без вебзахисту**; для публікації використовуйте тільки захищений wsgi.application. Готівка не змінює банківський залишок, відображається у відповідному місяці й враховується як змінна. Початковий запас готівки невідомий: рахунок готівки показує лише записані рухи, його залишок не звіряємо й не видаємо за фактичний гаманець. Зарплатні періоди PRD та спільні частки 50/50 залишаються окремими функціями; контрольні цифри не підмінюємо.

## Тести

```sh
uv run python -m unittest discover -s tests -v
```

Перевіряються обидва контрольні місяці, повторний імпорт, залишки/валюта/fixed, вхід/вихід/прострочення/ротація пароля, приватність маршрутів, CSRF, прив’язка форми до сесії, дублі, 1 PLN після перезапуску, захист від HTML-вставки, відновлення проєкції після збою запису та резервна копія без відновлення старих сесій.

## Дані й файли

- examples/ — лише незмінені штучні виписки з умови та їх походження/хеші; дозволені для відтворення після клонування. Справжніх виписок тут бути не повинно.
- data/ — лише читання. data/, transactions.beancount, report.html, .venv/ не потрапляють у git.
- main.beancount — рахунки, два початкові залишки й нативні query; import.py генерує банківський журнал; категорії та fixed задає тільки rules.csv.
- homework/ — продуктовий документ, декомпозиція та кроки частини 2.

До публічного Git не додаються runtime/, .env, env.json, бази та їх WAL/SHM/journal-файли, резервні копії, приватні ключі, журнали сервера, віртуальні середовища й службові файли редакторів. CSV дозволено лише для rules.csv та двох перевірених прикладів examples/; Beancount — лише main.beancount. Паролі та секрети передаються окремо від репозиторію. [Аудит готовності до GitHub](homework/20-publication-audit.md).

Локальні тести пройшли; у Chrome перевірено мобільний сценарій і розміри 320/375/390/430/768/1280 px. Користувачка також підтвердила перевірку опублікованого HTTPS-трекера на телефоні. Доступність має зберігатися до 09.11.2026 включно; фінальне оцінювання належить викладачу. Посилання й тестовий пароль для здачі передаються окремо, не в публічному README. Код опубліковано в [GitHub](https://github.com/labzona/my-finance-tracker), гілка main зі збереженою історією. Налаштування PythonAnywhere не змінювалися.
